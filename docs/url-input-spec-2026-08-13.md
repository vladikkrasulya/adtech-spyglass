# Специфікація: обробка вставленого URL у request-декодерах (2026-08-13)

> **Historical snapshot (2026-08-13).** This specification preserves the decisions taken at that
> date from the measurements in the companion research snapshot; it is a proposal, not the shipped
> contract. Use the [platform baseline](../specs/000-platform-baseline/plan.md) for current behavior
> and the [Spec Kit roadmap](../specs/ROADMAP.md) for active work.

> **Статус: рішення до реалізації, не заплановані роботи.** Перетворення на роботу — через
> `speckit.assess` за [ROADMAP](../specs/ROADMAP.md). Заміри й контекст —
> [дослідницький зріз](./silent-failures-research-2026-08-13.md).

Усі факти заміряні на Node 22.23.2, Chrome 151, Firefox 140esr; розбіжностей між рушіями немає.

## 1. Стан зараз — три підтверджені дефекти

**D1. `_raw` порушує задокументований контракт.**
`_canonical.js:45` обіцяє «Original query params verbatim». `_authenticated-json-feed.js:30`
будує його з `parsedUrl.searchParams.entries()`, який percent-декодує. Заміряно на живому
декодері:

```
вхід   cb=%%CACHEBUSTER%%
_raw   cb=%<U+FFFD>CHEBUSTER%%
```

Гине будь-який макрос `%%NAME%%`, де перші дві літери імені утворюють валідну hex-пару. З 25
перевірених імен гине 10: `CACHEBUSTER`, `AD_UNIT`, `AD_UNIT_PATH`, `ADV_DOM`, `CATEGORY_IDS`,
`DESCRIPTION_URL`, `DEVICE_ID`, `DEST_URL`, `EARNINGS`, `BACKFILL`. Виживають `CLICK_URL`,
`AUCTION_PRICE`, `CORRELATOR`, `CREATIVE_SIZE`, `TIMESTAMP`. Помилки не кидається, `u.href`
виглядає цілим.

**D2. Відмова без причини.**
`index.js:46` ловить виняток `new URL()` і повертає `null`. `index.js:72` повертає `null` і
тоді, коли жоден декодер не взявся. Для викликача це один сигнал. Заміряно: шість із восьми
способів вставити робочий URL дають `null` без пояснення.

**D3. Тихе псування хвостом.**
`?query=shoes)` приймається, у `_raw.query` лягає `"shoes)"`.

## 2. Правило межі

> Ремонтувати можна лише те, що додало **середовище передачі**. Усе, що є частиною
> **корисного навантаження** — шлях, імена й значення параметрів, їхній регістр, макроси —
> недоторкане.
>
> Кожен ремонт видимий: якщо рядок змінено, у результаті є запис про це.
>
> Регістронезалежне **зіставлення** ремонтом не є. Воно нічого не змінює у вході й живе в
> декодері, а не в нормалізації.

| Випадок                             | Транспорт чи навантаження            | Рішення                           |
| ----------------------------------- | ------------------------------------ | --------------------------------- |
| `"url"`, `<url>`, `[md](url)`       | транспорт                            | зняти, повідомити                 |
| хвостові `) , . ;`                  | транспорт                            | зняти за правилом GFM, повідомити |
| `&amp;`                             | транспорт                            | розкодувати один раз, повідомити  |
| відсутня схема                      | протокол                             | додати `https://`, повідомити     |
| невидимі символи                    | транспорт                            | зняти, повідомити                 |
| `/SEARCH`, `FORMAT=`, `format=JSON` | **навантаження**                     | не чіпати, зіставляти в декодері  |
| `%%CACHEBUSTER%%`                   | **навантаження**                     | не чіпати, зберегти дослівно      |
| `?a=1b=2`                           | **навантаження**, структура невідома | відмова з поясненням              |

## 3. Три шари

```
вставлений рядок
   │
   ├─► Шар 1  ремонт входу        новий файл _input-repair.js
   │          повертає { text, repairs[] }
   │
   ├─► Шар 2  парсинг              new URL() у index.js
   │          + сирий розбір query
   │
   └─► Шар 3  розпізнавання        detect() у декодерах
              регістронезалежне зіставлення
```

### Шар 1 — `_input-repair.js` (новий)

Застосовується **завжди**, не в `catch`. Причина заміряна: `?a=1&amp;b=2` і `?q=shoes)` не
кидають помилки, тож стратегія «лагодити лише коли впало» їх не побачить.

1. **trim** країв
2. **невидимі символи** — вирізати `U+200B`, `U+00AD`, `U+FEFF`, `U+2028`, `U+2029`, `U+0000`;
   `U+00A0` замінити на пробіл. Заміряно: `new URL()` вирізає TAB, LF, CR і **не чіпає жодного
   з цих** — вони проїжджають у запит як `%E2%80%8B`, `%C2%AD`, `%00`
3. **обгортки** — симетричні `"…"`, `'…'`, `` `…` ``, `<…>`, `(…)`; markdown `[текст](url)` —
   витягти другу групу
4. **хвостова пунктуація** — за GFM autolink: `? ! . , : * _ ~` зрізати завжди; `)` зрізати
   лише коли закриваючих більше за відкриваючі у всьому рядку; `;` — лише коли схожий на хвіст
   HTML-ентіті. Правило GFM дослівно
5. **`&amp;` → `&`** — один прохід, і лише де за ентіті йде `ім'я=`, **де ім'я не містить `;`**.
   Практично: `/&amp;(?=[A-Za-z0-9_\-[\]%.]+=)/g`.

   Виключення `;` з класу імені — не косметика, воно робить крок ідемпотентним за побудовою.
   Наївна заміна не ідемпотентна: `?x=a&amp;amp;b=2` за перший прохід дає `?x=a&amp;b=2`, за
   другий `?x=a&b=2`. Рекурсивна до нерухомої точки ламає вкладений закодований URL у
   параметрі-редіректі. Guard знімає обидві проблеми: `&amp;amp;b=2` не збігається (після
   `&amp;` йде `amp` і далі `;`, а не `=`), тож подвійно екранований вхід лишається недоторканим
   і повторний прогін нічого не міняє.

   Заміряно на дев'яти випадках — звичайний escape, кілька входжень, подвійне й потрійне
   екранування, ентіті в кінці, ентіті без `ім'я=`, справжній параметр `amp;b`, вкладений
   `%26amp%3B`, сусідні макроси: ремонт спрацьовує там, де треба, і **всі дев'ять ідемпотентні**.

   Подвійне екранування не ремонтується, а **повідомляється**: `&amp;` перед `amp;` є
   неоднозначним (чи то відправник екранував двічі, чи то справді існує параметр `amp;b`), а за
   §5 неоднозначну структуру ми не вгадуємо. Детектор — `/&amp;(?=amp;)/`

6. **схема** — якщо `new URL()` кидає, або `protocol` не `http:`/`https:`:
   - якщо між `:` і першим `/` число 1…65535 → це `host:port`, додати `https://`, перепарсити
   - інакше лишити (`mailto:`, `javascript:` ловляться далі як заборонені)
   - Заміряно: `adserver:8080/feed` → `protocol="adserver:"`; `ad-server:8080/feed` теж (дефіс
     легальний у схемі, типове ім'я Docker-хоста); `ad_server:` і `127.0.0.1:` кидають помилку

Кожен крок, що змінив рядок, дописує запис у `repairs[]`. Крок, який виявив неоднозначність і
свідомо нічого не зробив, дописує запис у `warnings[]`. Сигнатура шару:
`repairInput(input) → { text, repairs[], warnings[] }`.

**Ідемпотентність — інваріант, не побажання.** `repairInput(repairInput(x).text).repairs` має
бути порожнім для будь-якого `x`. Якщо якийсь крок цього не витримує, виправляється крок, а не
тест: інструмент, що змінює власний вихід на другому прогоні, є рівно тим тихим псуванням, проти
якого все це будується.

### Шар 2 — парсинг

`new URL()` на відремонтованому рядку. Плюс **сирий розбір query**: розбити `u.search` по `&`,
потім по першому `=`, **без percent-декодування**. Це і є `_raw`.

Закриває D1 без маскування макросів: декодовані значення лишаються там, де потрібні
(`device.ip`, `site.page`, `user.id`), а `_raw` виконує обіцянку.

Безкоштовний детектор: якщо `searchParams.get(k)` містить `U+FFFD`, а `_raw[k]` — ні, значення
побите percent-декодуванням. Попередження з іменем параметра. Працює й на макросах, яких ми ще
не бачили — реєстр не потрібен.

### Шар 3 — розпізнавання

`url-search-feed/index.js:22-24` зіставляє з урахуванням регістру:

```js
if (parsedUrl.pathname.replace(/\/+$/, '') !== PATH) return false;
return q.get('format') === 'json' && q.has('feed') && …
```

Замінити на регістронезалежне зіставлення шляху, імен і перелічуваних значень. Регістр входу
**не змінюється** — лишається в `_raw` і `url` як був. RFC 3986 §6.2.2.1: регістронезалежні
тільки схема й хост. Тому ми не нормалізуємо, ми зіставляємо.

## 4. Контракт результату

`decodeRequest` більше не повертає `null` на дві різні події:

```js
{ ok: false, reason: 'unparseable', detail, repairs }  // не URL навіть після ремонту
{ ok: false, reason: 'no_decoder',  parsed, repairs }  // URL валідний, фід не впізнано
{ …canonical, repairs, warnings }                      // впізнано
```

`repairs[]` — `{ step, before, after }` на кожну зміну. `warnings[]` — те, що **не**
ремонтували, але вважаємо підозрілим: побиті макроси, `amp;`-подібні імена, невідповідність
регістру відомим значенням.

UI зобов'язаний показати `repairs` як diff і дати скопіювати **відремонтований** URL. Інакше
інженер бачить зелений статус, копіює сирий рядок у DSP і отримує аварію.

## 5. Що НЕ ремонтувати

- `?a=1b=2` — немає роздільника; невідомо, це значення `1b=2` чи два параметри
- `feed..example`, `feed.example_com` — побитий хост
- `%%CACHEBUSTER` без закриття, `${AUCTION_PRICE` — обірваний макрос
- схеми, крім `http:` і `https:`. Заміряно: `javascript:alert(1)` парситься без помилки, тож
  потрібен явний чорний список
- кілька URL в одній вставці (дамп curl)

## 6. Тести

15 варіантів вставки; 10 макросів, що гинуть, і 5, що виживають; `adserver:8080` і
`ad-server:8080`; `&amp;amp;` подвійне екранування; всі шість невидимих символів; `?q=(shoes)`
проти `?q=shoes)`; `javascript:` і `mailto:`.

Окремий тест на ідемпотентність: повторний прогін відремонтованого рядка дає порожній
`repairs[]`.
