# Data Model: Dependency and Sentry Refresh

This feature adds no user, application, analytics, or persistence entities. Its relevant state is
configuration and build metadata.

## Dependency Graph

- **Identity**: root `package.json` plus `package-lock.json`
- **Fields**: package name, requested range, resolved version, integrity, dependency edges, dev flag,
  platform/engine constraints
- **Rules**: the lockfile is generated by ordinary npm resolution; clean `npm ci` must reproduce it;
  full and production-only audits must each return zero findings; no unrelated direct major changes
- **Relationships**: root app depends directly on `@sentry/node`; workspace packages remain unchanged;
  Sentry owns the affected OpenTelemetry production subtree; jsdom owns the development-only undici
  subtree

## Local Sentry Configuration State

- **Identity**: process-local state in `lib/logger.js`
- **Inputs**: `SENTRY_DSN`, `NODE_ENV`, optional `BUILD_SHA`
- **State**:
  - `disabled`: DSN absent or test environment; capture is a no-op and readiness is false
  - `invalid`: SDK cannot retain a parsed DSN or initialization throws; capture is a no-op and
    readiness is false
  - `configured`: SDK client retains a parsed DSN; readiness is true and explicit capture/flush are
    enabled
- **Rules**: `configured` proves only local parsing/initialization; it does not imply DNS, network,
  authentication, ingestion, storage, alerting, or delivery success
- **Transitions**: evaluated once at module load; process restart is required to evaluate changed
  environment configuration

## Health Projection

- **Identity**: `GET /api/health` field `sentry.ready`
- **Type**: boolean
- **Source**: injected `sentryReady()` function; absent injection maps to false
- **Rules**: anonymous and authenticated shapes remain compatible; DSN host, project ID, credentials,
  or error detail are never exposed; database health continues to own the HTTP 200/503 status
- **Relationship**: projects only the process-local configuration state and does not query the Sentry
  target

## Test Envelope

- **Identity**: synthetic event captured inside an isolated child process
- **Fields**: synthetic error, non-sensitive context, synthetic invalid-domain DSN, build placeholder,
  bounded flush timeout
- **Rules**: custom in-memory transport only; no socket/network egress; no payload bodies, production
  identifiers, user data, credentials, or private incident content
- **Lifecycle**: created, inspected, and discarded inside one test process; never persisted

## Verification Evidence

- **Identity**: command/outcome records in `tasks.md`
- **Fields**: exact command, exit status, relevant zero-finding/tree/smoke outcome, sandbox limitation if
  any, timestamp or current-run context
- **Rules**: do not hard-code suite totals in long-lived contracts; do not claim an unrun gate passed;
  production delivery is not repository verification evidence
